# Markdown Desk — Requirements Specification & Regression Baseline

**Product:** Markdown Desk · by Andrew Michelis / KnackMentor
**Spec version:** 1.23 · corresponds to app **v3.53** · 2026-07-17
**Purpose of this document:** the single source of truth for what the tool must do. Every requirement has a stable ID. New features add IDs; changes amend them; nothing is deleted (deprecated items are marked, not removed). Any release must hold **all** non-deprecated requirements — this is the regression checklist.

---

## 1. Product identity & scope

Markdown Desk is a **self-contained, single-file HTML tool** for reading, writing, and annotating local Markdown files, Joplin-style, with project-folder awareness, freehand/shape/label ink, highlights, notes, bookmarks, PDF/PNG/ZIP export, and PWA installability. It targets desktop Chromium-family browsers (File System Access API) with a Wacom-class stylus as a first-class input.

---

## 2. Architectural invariants (ARC)

| ID | Requirement |
|----|-------------|
| ARC-01 | The entire tool ships as **one HTML file** (`markdown-desk.html`). No build step, no CDN, no runtime network dependency for core function. |
| ARC-02 | Third-party libs are **embedded**: marked 12.0.2, DOMPurify 3.1.6. All rendered HTML passes through DOMPurify. |
| ARC-03 | Works from **`file://`** and from **https** hosting (knackmentor.com). Features that require https (PWA install, clipboard read) degrade gracefully on `file://`. |
| ARC-04 | **Privacy:** no telemetry, no server storage; all user data lives in the browser (IndexedDB, localStorage) and in user-visible `.mdesk` files next to their documents. |
| ARC-05 | A **version badge** (bottom-left, and in Help) identifies the running build; every released change bumps it. Used to detect stale deployments/caches. |
| ARC-07 | **Markdown stays human-readable plain text.** The tool never writes binary or base64 payloads into `.md` content; pasted media becomes real files on disk or the paste is refused with an explanation. (v3.36) |
| ARC-06 | Optional companion files (PWA kit) are **generated by the tool itself**; their absence never breaks core function. |

## 3. Documents & files (DOC)

| ID | Requirement |
|----|-------------|
| DOC-01 | Open `.md` files via file picker (Ctrl+O), drag-and-drop anywhere, project tree click, or relative-link navigation. |
| DOC-02 | **Project folder** open: recursive scan (depth ≤ 8, skips dotfiles & `node_modules`), tree in sidebar, plus a full-file index used for asset resolution and ZIP fallback. |
| DOC-03 | Save (Ctrl+S) writes through the FS Access handle; **Save-As** rebinds the tab, renames it, and (DOC-07) adopts into the project. |
| DOC-04 | **New file** (Alt+N, toolbar, empty-state): creates "Untitled N.md" with no handle; first Save routes to Save-As. |
| DOC-05 | **Tabs:** multiple docs; Alt+←/→ cycle, Alt+1–9 jump, Alt+W close. Session (open tabs + active) resumes on next launch. |
| DOC-06 | **Recents:** last 15 files with inline content snapshot (≤ 400 KB) for handle-less reopen. Clearing recents clears **only the list** (see PER-07). |
| DOC-07 | Saving a doc inside the open project folder **adopts** it: computes the project-relative path, enabling sidecar persistence. Saves outside any project show a one-time notice that annotations stay browser-only. |
| DOC-08 | Relative `.md` links in the preview open **in-app**; images resolve through project handles to blob URLs. |
| DOC-10 | A **tree-fold cycle button** beside the project actions cycles: fold all folders → restore the user's last manual layout → unfold all → … . The remembered baseline is re-learned **only** from the user's manual folder toggles — cycling through fold/unfold, however many times, never overwrites it. Button icon/tooltip always announce the *next* operation; hidden when no folders exist. (v3.34) |
| DOC-09 | Pasting an image stores it as a real file with fallback chain: (1) `_assets/` beside the document; (2) directly beside the `.md`, named `<mdname>.<img>.<ext>` like the sidecar (same path, name changes); (3) if no writable location exists, the paste is **refused with guidance** — base64 is never embedded (ARC-07). (amended v3.36) |

## 4. Editing (EDT)

| ID | Requirement |
|----|-------------|
| EDT-01 | Three modes — Edit / Split / Preview — via Ctrl+1/2/3 and toolbar; mode persists. Inactive panes are **fully hidden** (no bleed-through; see RG-01). |
| EDT-02 | GFM rendering (tables, task lists, strikethrough); no line-break-as-`<br>`. |
| EDT-03 | **Markdown toolbar** above the editor (edit & split): Bold, Italic, Strikethrough, Inline code — all **toggling** (unwraps if already wrapped, including when the selection sits inside the marks). |
| EDT-04 | Heading dropdown applies H1–H4 or back-to-text to all selected lines, replacing any existing level. |
| EDT-05 | Line-toggling list actions: bulleted, numbered (renumbers 1..n), task `- [ ]`, quote `>`; each removes its own prefix when already present. |
| EDT-06 | Insert actions: link `[…](url)` (Ctrl+K), image `![…](path)`, 3-column table template, fenced code block (wraps selection), horizontal rule. Block inserts respect line boundaries. |
| EDT-07 | Shortcuts: Ctrl+B bold, Ctrl+I italic, Ctrl+K link, Ctrl+Shift+X strike; Tab inserts 4 spaces. |
| EDT-08 | Text insertion uses `execCommand("insertText")` (native undo) **with a `setRangeText` fallback** where unavailable (RG-08). |
| EDT-09 | Word & character counts live in the status bar. |
| EDT-11 | **Live markdown styling in the editor** (edit & split): a metric-safe backdrop renders `**bold**`, `*italic*`, `~~strike~~`, `` `code` ``, headings (bold+accent, same size), list/quote/fence/HR markers and links styled **while the syntax characters remain visible**, updating on every keystroke; fenced code content is exempt from inline styling; alignment with the caret is glyph-exact (no font-size changes). (v3.36) |
| EDT-10 | **Document undo/redo** (Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z) works in **every mode** — edit, split, preview, editor focused or not — covering typing (grouped into ~1 s bursts), every toolbar action, and every selection-chip format, each programmatic action being exactly one step. Per-doc stacks (cap 120). Pen mode routes to ink undo; notes panel and the label editor keep native undo. (v3.31) |

## 5. Preview & reading (VIEW)

| ID | Requirement |
|----|-------------|
| VIEW-01 | Article column width is user-cyclable — Narrow 82ch / Wide 100ch (default) / X-Wide 120ch / Full — persisted; goal: wide tables without ugly horizontal scrollbars. |
| VIEW-02 | Preview **zoom** 70–160 % in 10 % steps (A− / % / A+ in status bar; % resets); persisted. Zoom & width changes re-run ink resize and PDF-guide geometry live. |
| VIEW-03 | Light/dark theme toggle; "ink" pen color follows theme; marker blend flips multiply→screen in dark. |
| VIEW-04 | **Outline** (headings) in sidebar; click scrolls; reflects live edits. |
| VIEW-05 | Per-doc scroll position persists and restores. |
| VIEW-06 | **Tail-space control** (status bar, persisted) cycles Auto / Compact / Half page / Full page for the whitespace after the text: Auto gives short docs full-viewport drawing room and long docs a modest 96 px tail; Compact packs to the text; Half/Full add ink workspace. (v3.35) |
| VIEW-09 | **Interactive tables** in the preview: each table gets a scrollable wrapper and a hover toolbar with **Fit** (zoom the table to the article column so nothing is cut from the PDF), **100 %** (full reset), and **Wrap** (toggle cell line-wrapping). Its **grid lines are draggable** — vertical edges resize columns (via `colgroup`, `table-layout:fixed`), horizontal edges resize rows — with zoom-corrected math. **Fit means "one line per cell, scaled into the column"** — a wrapping (non-overflowing) table gets no-wrap applied first, then scaled. **Double-clicking a header cell toggles no-wrap for that single column** (e.g. IDs stay on one line while prose columns wrap). A status-bar **⟲ Doc** button resets all of the active document's table tweaks after confirmation. Layouts persist per document — in IndexedDB **and in the `.mdesk` sidecar** (they count as sidecar-worthy content) — and re-apply after every render; all styles are inline so PDF export reproduces them. (v3.39, extended v3.41) |
| VIEW-08 | **Split-view synchronized scrolling** (toggleable in the status bar, default on, persisted): scrolling either pane scrolls the other so corresponding sections align at the **reading line — 20% from the pane top** (matching natural eye position; was the vertical center through v3.44). Mapping precision is layered: **block-level anchors** (every top-level source block paired with its rendered element, line-accurate via per-line backdrop spans) when a source block scanner agrees with the render's child count; **heading anchors** when it doesn't; **proportional** as the last resort. The toggle label states its state and click action explicitly ("Sync: On/Off"). Inside table blocks, every source `|` row additionally anchors to its rendered `<tr>`, keeping long tables aligned internally. (rows v3.43) Targets are **clamped**: a shorter pane pins at its start/end rather than fighting. Programmatic scrolls are **echo-suppressed** (expected-position consume) so panes never ping-pong. Anchors invalidate on render, resize, **mode switch**, and width/zoom/tail changes. (v3.37, hardened v3.40) |
| VIEW-07 | In **split view the rendered preview pane sits on the LEFT**, editor on the right. (v3.35) |

## 6. Highlights, notes, bookmarks (ANN)

| ID | Requirement |
|----|-------------|
| ANN-01 | Selecting text in preview/split shows a floating **chip**: Highlight, ＋Note, divider, **B / I / S / code**. Chip survives mousedown (no selection loss). |
| ANN-02 | Highlights anchor by **true text offsets** with prefix/suffix context; re-anchoring after edits picks the nearest matching occurrence (context-scored), never a wrong duplicate. |
| ANN-03 | Chip format buttons edit the **markdown source**: locate the exact selection via context scoring and **toggle** the marks — applying on plain text and removing them when the selection is already formatted (including selections inside the rendered `<del>`/`<strong>`/… elements). Unmappable selections produce an explanatory banner, never a wrong edit. |
| ANN-04 | ＋Note appends the quoted selection to the per-doc **notes panel** (Ctrl+.), which persists per doc. |
| ANN-05 | **Bookmarks** (Ctrl+D) store position + label per doc; listed in the sidebar Bookmarks section; click navigates. |
| ANN-06 | Highlights render in preview and (optionally) in PDF export. |

## 7. Ink layer (INK)

### Pens & drawing
| ID | Requirement |
|----|-------------|
| INK-01 | Two canvases: **marker layer** (translucent, multiply/screen blend) and **solid layer** (pens, shapes, labels). |
| INK-02 | Pens: marker yellow/green/pink (17 px, α .9); red / blue / theme-ink (2.2 px). Freehand strokes are EMA-smoothed; quadratic segments. |
| INK-03 | Shapes: rectangle, ellipse, arrow (tail→tip drag), ghost preview while dragging. |
| INK-04 | Eraser tool **and stylus barrel-button** erase by proximity; pen mode shows a dot cursor. |
| INK-05 | The ink surface spans the **entire document** (sanity cap 200 000 px CSS): the pointer-event surface is bufferless and full-height, while raster tiles are **virtualized** — materialized only around the viewport (±1 tile, 2 400 px each at full pixel ratio) and dropped on scroll-away; strokes are vector data and tiles redraw when their region returns. The pen must work at ANY scroll depth; memory stays bounded regardless of document length. (amended v3.38, v3.47, v3.52) |

### Anchoring
| ID | Requirement |
|----|-------------|
| INK-06 | New strokes anchor to the underlying **element** (v3: `a={t,i,w,h}`), scaling with that element across width/zoom/theme changes; strokes with no element fall back to column anchoring (v2: width `w`). Legacy v2 strokes keep working. |
| INK-07 | Every geometric consumer (draw, hit-test, bbox, move, export, clipboard) goes through the shared **strokeTransform** so v2/v3/label kinds behave identically. |

### Selection & manipulation
| ID | Requirement |
|----|-------------|
| INK-08 | Select tool (✥): click selects; click inside an existing selection keeps the group; **marquee** drag on empty area selects all intersecting strokes; Shift-click toggles membership; Escape clears; Ctrl+A selects all ink and switches to ✥. |
| INK-09 | Dragging moves the **whole selection**; each stroke re-anchors at drop. Group move/delete/recolor/restyle are each **one** undo step. |
| INK-10 | Del/Backspace deletes the selection (outside text fields). Swatch click **recolors the selection and keeps it selected** — tool switches to draw only when nothing is selected (RG-02). |
| INK-11 | **Clipboard:** Ctrl+C/X/V on selections; pasted groups offset +16 px per repeat, arrive selected under ✥, re-anchor to target content. Works **across documents** and — via a tagged system-clipboard payload (`MDESK-INK-v1:`) — **across tool instances/windows**; falls back to the internal clipboard if clipboard permission is denied. |
| INK-12 | **Undo/redo** (Ctrl+Z/Y in pen mode): action history (cap 200/doc) covering add, delete, erase, move, recolor, restyle, clear, paste — including grouped N-variants; per-doc isolation. |

### Text labels
| ID | Requirement |
|----|-------------|
| INK-13 | **T tool:** click places an inline editor at that point; Enter commits, Esc cancels; committing empty text on an existing label deletes it. |
| INK-14 | Labels have **font** (Sans/Serif/Mono/Hand), **size** (12–48), **color** (picker; pen swatches also set it — **including the theme-ink/black pen**, resolved via `toolColor`). Style controls show while the T tool is active **or while ✥ has a label selected**, and restyling a selection updates metrics and is undoable. |
| INK-16 | Pen-mode plain-key shortcuts (no modifier, not while typing): **1** red, **2** blue, **3** theme-ink/black, **4/5/6** markers Y/G/P, **`** toggles the eraser. Number keys route through the swatch path, so with a live selection they recolor it and keep the selection. (v3.32) |
| INK-15 | Labels are first-class strokes: anchored, hit-testable, movable (double-click with ✥ to edit), group-selectable, clipboard-able, persisted, PDF-baked, PNG-exported. |

## 8. Persistence (PER)

| ID | Requirement |
|----|-------------|
| PER-01 | Per-doc state (scroll, notes, bookmarks, highlights, ink/labels) persists in IndexedDB (`mdesk`/`kv`, key `state:<docKey>`), debounced. |
| PER-02 | Doc keys: project docs `p:<relpath>`; picker-opened standalone docs `p:<name>`; content-only docs `f:<name>`. |
| PER-03 | Project docs also persist to a **sidecar** `<name>.md.mdesk` next to the file, plus a root `.mdesk` project file — making annotations portable with the folder. Legacy sidecar names are read once, migrated, and deleted. |
| PER-04 | Sidecar/state writers are **frozen during ZIP export** and flushed before it (RG-05). |
| PER-05 | **State rescue:** opening a doc whose key holds no meaningful state searches all stored keys for the same filename under other contexts (`f:<name>`, `p:<name>`, `p:…/<name>`) and migrates the **newest non-empty** match — bookmarks/notes must never appear lost due to key-context changes (RG-09). |
| PER-06 | **Privacy wipe** (Ctrl+Shift+R + Help button): confirm → clear IndexedDB + `mdesk-*` localStorage → reload. `.mdesk` files on disk are untouched and say so. |
| PER-07 | Clearing the recents list never deletes any state; the confirmation says so explicitly. |
| PER-08 | UI preferences persisted in localStorage: mode, theme, sidebar width & section fold states, article width, zoom, PDF-guide toggle. |

## 9. Export & interchange (EXP)

### PDF
| ID | Requirement |
|----|-------------|
| EXP-01 | Export dialog with include-highlights / include-ink options; opens a print window (user prints to PDF). |
| EXP-02 | Print window strips `@media` rules from copied CSS and **locks the column** to the on-screen preview width so geometry matches the screen. |
| EXP-03 | Ink/labels bake **per anchor element** into the content (2× supersampled images, `max-width:none`); strokes without element anchors render as whole-page overlays cropped to the column. Marker translucency is rasterized (blend modes don't survive print). |
| EXP-04 | Export height is pinned (stylesheet-level `!important`, incl. `overflow:hidden`) to `min(20000, max(TEXT CONTENT, ink extent) + 20)` where text content **excludes the decorative tail padding** — precedence: content first, ink second, screen whitespace never earns PDF pages; no trailing blanks, no clipped ink (RG-03/RG-04). The on-screen PDF-area guide uses the same formula. (amended v3.35) |
| EXP-05 | Every export logs one `[mdesk pdf] {…}` diagnostics line (version, stroke counts, exportH, extents). |
| EXP-06 | Optional **PDF-area guide** (dashed frame + dimmed outside) previews export bounds; grows with ink; hidden in edit mode; persisted. |
| EXP-07 | **PNG export** (pen toolbar): both ink layers composited on white, cropped to column + ink extent. Rendered markdown text is *not* included (accepted limitation LIM-03). |

### ZIP snapshot

## 13. Regression guards (RG) — hard-won invariants; test on every release

| ID | Guard | Origin |
|----|-------|--------|
| RG-01 | No stylesheet rule may set `display` on `.pane`/`.pane.editor` outside the `body.mode-*` selectors — higher-specificity rules silently defeat pane hiding. | v3.30 split→view glitch |
| RG-02 | Never call `setTool()` (or anything that clears `selSet`) **before** acting on the current selection in an input handler. Recolor/restyle must retain selection. | v3.30 dead recolor |
| RG-03 | In the print/export stylesheet, pinned height/overflow must be `!important` **inside the stylesheet** — stylesheet `!important` beats inline styles. | v3.22 missing ink |
| RG-04 | All export canvas dimensions clamp ≤ 16 000 px and guard non-finite extents; mis-anchored strokes must not inflate export height. | v3.20 blank PDFs |
| RG-05 | Any long async file operation: acquire pickers on the **first** user gesture; freeze background writers; enumerate directories before reading files (mid-walk writes invalidate Chromium iterators). | ZIP export failures |
| RG-06 | Failed saves must remove partial files (`handle.remove()`); export always reports success/failure explicitly. | stray 0-byte zips |
| RG-07 | Exactly one manifest `<link>`; prefer a real manifest file over data-URI; never reintroduce a static manifest into the HTML head. | v3.26/27 install failures |
| RG-08 | Any `execCommand` usage needs a modern fallback. | v3.29 toolbar |
| RG-09 | Doc-state reads that find nothing must run the alternate-key rescue; rescue must be newest-wins, filename-scoped, with no false positives and empty states skipped. | bookmark loss |
| RG-10 | Text-offset (not DOM-node) anchoring for highlights; occurrence choice must be context-scored. | wrong-occurrence marks |
| RG-11 | Ink offsets derive from live rect mapping + ResizeObserver; any layout change (zoom, width, sidebar) triggers `resizeInk` + guide refresh. | drifting ink |
| RG-12 | The selection chip must `preventDefault` on mousedown so browser selection survives clicks. | dying chip |
| RG-13 | Keyboard shortcuts (Del, Ctrl+A/C/X/V/Z/Y) must not fire while typing in editor, notes, or the label editor (stopPropagation in the label input). | label editor |
| RG-14 | UI reflecting selection state (e.g., label style controls) must update on **selection changes**, not only tool changes — piggyback on `drawInk`. | v3.30 hidden controls |
| RG-25 | Pointer input hardening: `setPointerCapture` is wrapped (a NotFoundError must never abort a stroke) and `getCoalescedEvents()` results are used **only when non-empty** — some pen drivers and all synthetic pointers return empty lists, which silently dropped every stroke point. The release battery (TST-08) runs pen-typed pointer events, not only mouse: mouse-only input testing masked this entire class. | v3.51 broken stylus |
| RG-24 | The print surface must **never clip content**: column width is locked (ink anchoring), height is `min-height` + `overflow:visible` so print-side reflow (zoom-scaled tables, engine rasterization differences) grows the document instead of silently cutting tail pages. Empty-tail suppression comes from padding removal, never from height clamping. Verified by injecting artificial reflow into the print window and asserting the end sentinel still renders. | v3.49/50 truncated PDFs |
| RG-23 | **PDF text height is never clamped by ink-surface limits.** `exportH` derives from `textContentHeight()` unclamped (sanity ceiling 200 000 px); only ink overlay raster crops obey canvas ceilings (16 000 device px). A document taller than the 20 000 px ink cap must print ALL its text — ink simply cannot exist below the cap, which is a drawing limitation (LIM-07), not a printing one. | v3.49 truncated PDFs |
| RG-22 | Sync **driver lock**: the actively scrolling pane owns the coupling for 250 ms per event; the passenger pane's handlers stay silent (echo-consume alone leaks stale async echoes under rapid event streams). Programmatic pane movement must NEVER occur mid-gesture in the pane the user is interacting with — text selection with auto-scroll and multi-click gestures are the regression tests. | v3.46 broken selection |
| RG-21 | **Exactly one scroll-sync system may exist.** A legacy v1 proportional `syncScroll` coexisted with the anchored engine through v3.43 — both fired per scroll and the proportional settle always won, making anchored sync appear broken across three releases. Any new pane-coupling behavior must remove or subsume its predecessor, verified by a real-browser (Playwright) alignment measurement, not only jsdom wiring tests. | v3.44 sync fights |
| RG-20 | Ctrl+Z/Y routing: **editor-focused undo is always document undo**, regardless of pen state — `setRangeText`-based edits are invisible to native textarea undo, so falling through to it loses GUI toolbar operations. Pen-ink undo applies only when pen is on AND focus is outside the editor — and **focus follows interaction**: starting a draw gesture on the ink canvas blurs the editor, so Ctrl+Z after drawing targets the ink; typing refocuses the editor and undo targets the document again. | v3.40 heading undo, v3.53 stylus undo |
| RG-19 | The editor's transparent text depends on the backdrop: `updateEditorHighlight()` must run on **every** path that changes `editor.value` (guaranteed via the top of `render()`), and the highlighter is wrapped so a failure falls back to plain text — the editor must never appear blank or stale. | v3.39 broken edit view |
| RG-17 | Ink layers are **tiled** (8 000 css px per tile) so every device-pixel buffer stays ≤ 16 000 px per side at **full pixel ratio** — never downscale resolution to stay within GPU limits (the v3.38 approach made ink blurry/dull), never exceed the limits (silent software rasterization = the v3.38 lag). Strokes crossing tile boundaries must render continuously; per-tile contexts carry a `translate(-tileTop)` transform so all drawing code uses absolute preview coordinates unchanged. | v3.38 lag → v3.47 dull ink |
| RG-18 | During an active stroke, layout reads are **cached** (`liveRects`: one canvas rect + preview box per stroke, invalidated on stroke end/scroll/resize) and live tail rendering maps **only the fresh point slice** — never per-event `getBoundingClientRect` or O(all-points) work on the pointer path. | v3.38 lag |
| RG-16 | Pens with `color:null` (theme-resolved) must never be read via raw `PENS[..].color` for label/UI colors — always resolve through `toolColor()`. | v3.31 black swatch |
| RG-15 | Version badge + Help version + internal `version` string bump together every release. | stale-deploy confusion |

## 14. Testing strategy (TST)

| ID | Practice |
|----|----------|
| TST-01 | Syntax gate: extract the main script, `node --check`, on every patch. |
| TST-02 | Integration harness: **jsdom** + `fake-indexeddb`, mocked FS handles, canvas Proxy contexts capturing `moveTo/lineTo/fillText` (+`measureText → {width}`), dialog polyfill, print-window mock parsing the written document. |
| TST-03 | Draw comparisons use **deduplicated coordinate sets** (pending animation frames double-draw; raw arrays are noisy). |
| TST-04 | Plant IndexedDB fixtures **before** app boot; fake-indexeddb has a cross-connection visibility artifact absent in real browsers — unit-test pure logic when it bites. |
| TST-05 | ZIP outputs validated with Python `zipfile` **and** Info-ZIP `unzip -t`. |
| TST-06 | Patch discipline: python exact-string replacement with per-patch `assert`, replacement text in named variables, applied-tags printed, file verified changed. |
| TST-07 | Every bug fix lands with a test that reproduces the failure first, plus its RG entry above if it revealed an invariant. |
| TST-09 | Real-browser geometry tests (Playwright + Chromium) for anything involving layout measurement: scroll-sync alignment error in px, canvas buffer sizes, table fit. jsdom cannot catch geometry bugs — it validated two "working" sync versions that lost every real scroll fight. |
| TST-08 | Minimum release battery: pane modes, editor toolbar actions, chip formatting, highlight anchoring, ink draw/select/move/undo, label lifecycle, clipboard (incl. two-instance), sidecar round-trip, rescue logic, PDF diagnostics line, ZIP round-trip, PWA modes, sidebar resize, zoom/width. |
